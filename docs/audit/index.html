What we check in the logs

  • Duplicate calls and retries — the same request paid twice: loops, retries replaying context, fan-out copying one prompt.
  • Failed but billed — errors after the payment settled.
  • Quote vs settled — what the provider quoted and what actually left the wallet.
  • Missing refunds — reversals that never arrived.
  • No per-task attribution — spend you cannot assign to a task, and why.

What you get

  • a report naming each leak, with the line or pattern it came from;
  • the fix order: first the leak with the largest recoverable amount;
  • a spend-limit configuration you can apply the same week;
  • if the logs show no leaks, the report says so — we do not invent findings.
